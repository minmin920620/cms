Final Defense Guide
Crime Mapping and Management System

1. Short System Introduction

The system is a Crime Mapping and Management System developed for recording, monitoring, mapping, and analyzing crime incidents. It helps police personnel, investigators, administrators, and LGU users manage crime records in one centralized web application. The system supports crime incident encoding, case status tracking, evidence management, barangay-based mapping, hotspot monitoring, analytics, report generation, notifications, audit logs, and user management.

Simple defense answer:
Our system is a web-based Crime Mapping and Management System. Its purpose is to centralize crime incident records, track case progress, manage evidence, display incidents on a map, identify hotspots, and generate analytics and reports for decision-making.

2. Problem Addressed by the System

The system addresses the difficulty of managing crime records manually or through scattered files. Without a centralized system, it can be hard to search records, monitor case status, consolidate evidence, identify crime-prone areas, and prepare reports. The system improves record organization, data retrieval, accountability, and decision-making.

  • Manual records are harder to search and update.
  • Case progress is difficult to monitor without a workflow.
  • Evidence can be separated from the case record.
  • Crime patterns are harder to analyze without maps and analytics.
  • Report preparation takes longer when data is manually counted.
  • User actions are harder to trace without audit logs.

6. Database Explanation

The database is normalized so that related information is stored in separate tables. This avoids repeated data and improves data integrity. For example, crime type names are stored in the crime_types table and referenced by crime_incidents through crime_type_id. Barangay information is stored once in barangays and referenced by barangay_id. Evidence, status histories, assignment histories, notifications, and audit logs are separated because one crime incident can have many supporting records.

7. Normalization Explanation

The database normalization follows UNF, 1NF, 2NF, and 3NF. In UNF, all data can be stored in one wide table, which causes repeating groups such as Evidence1, Evidence2, Status1, and Status2. In 1NF, repeating groups are removed and each field contains only one value. In 2NF, separate entities such as users, crime types, offense types, and barangays are moved to their own tables. In 3NF, event-based and supporting records such as evidence, status history, assignment history, notifications, and audit logs are separated to remove transitive dependencies.

Simple defense answer:
We normalized the database to reduce repeated data. Crime incidents store only the main case details and foreign keys. Other information, like users, barangays, crime types, evidence, status histories, notifications, and audit logs, is stored in separate related tables.

9. System Architecture Explanation

The system follows a three-tier architecture. The presentation layer is the user interface accessed through the browser, including login, dashboard, crime records, map, analytics, and reports. The application or business logic layer is Laravel, which handles routing, controllers, validation, authentication, role checking, workflow rules, and report generation. The data layer is the database and storage where crime records, users, barangays, evidence, histories, notifications, logs, and uploaded files are stored.

11. Workflow Status Explanation

The crime workflow starts when a report is received. The case may move to CIRAS recording, summary review, correction, data stored, IRF printed, IRF signature, blotter entered, UCPER compiled, resolved, and closed. This workflow allows the organization to monitor the progress of every crime incident and maintain a history of status changes.

Simple defense answer:
The workflow is used so users can see the current stage of a case. It also creates accountability because status changes are recorded in the system.

13. Common Final Defense Questions and Answers

Question: What is the main objective of your system?

The main objective is to provide a centralized web-based system for recording, managing, mapping, and analyzing crime incidents. It helps authorized users monitor cases, manage evidence, identify hotspots, and generate reports.

Question: Who are the users of the system?

The users are Administrator, Police Officer, Investigator, and LGU user. Each role has different access depending on their responsibilities.

Question: Why did you use Laravel?

Laravel was used because it provides organized MVC structure, built-in routing, authentication support, validation, database migrations, Eloquent ORM, and middleware for role-based access.

Question: What makes your system different from manual recording?

The system centralizes records, makes searching and updating easier, connects evidence to cases, tracks status history, maps crime locations, generates analytics, and records audit logs for accountability.

Question: How does the map help users?

The map helps users visualize where crime incidents happened. It uses coordinates and barangay data to support location-based monitoring and hotspot identification.

Question: What is the purpose of normalization in your database?

Normalization reduces duplicate data and improves database integrity. It separates users, barangays, crime types, offense types, evidence, status histories, notifications, and audit logs into related tables.

Question: What is the purpose of audit logs?

Audit logs record user actions, affected records, old values, new values, IP address, and user agent. This helps administrators trace activity and improve accountability.

Question: How do you protect sensitive data?

The system uses login authentication, hashed passwords, role-based middleware, protected routes, validation, and audit logs. Users can only access the modules allowed for their role.

Question: Why do you have different roles?

Different roles are needed because each user has different responsibilities. For example, administrators manage the whole system, police officers record incidents, investigators handle case progress, and LGU users view analytics for planning.

Question: What are the limitations of your system?

Possible limitations include dependence on accurate data encoding, availability of internet or local network connection, and the need for correct coordinates for reliable mapping. The system also depends on authorized users keeping records updated.

Question: What future improvements can be added?

Future improvements may include mobile access, SMS/email notifications, advanced predictive analytics, real-time GIS layers, integration with other police systems, and automated data import from official sources.

In conclusion, the Crime Mapping and Management System helps improve crime record management by centralizing incident data, supporting case workflow, managing evidence, mapping locations, identifying hotspots, generating analytics, and improving accountability through role-based access and audit logs.
