Normalization

Introduce the database before normalization.
1NF - Remove repeating groups. Each column must contain only one value (atomic values). Instead of multiple evidence or audit columns, each evidence file and audit action gets its own row.

Problem:

Offenses and evidence are stored in multiple columns.
If a crime has more evidence files, additional columns must be added.
Crime type, officer, barangay, and status information are repeated and difficult to maintain.

Example of 3NF:

Rule of 3NF: Remove transitive dependencies. A non-key attribute should depend only on the primary key. Final tables match the system database.

usersMain Fields
id (PK)name, email, role, phone, badge_number, avatar, is_active
crimesMain Fields
id (PK)case_number, title, crime_type_id, offense_type_id, barangay_id, dates/times, status, coordinates, reported_by, assigned_officer
evidenceMain Fields
id (PK)crime_id, file_path, storage_disk, file_type, file_name, uploaded_by, deleted_at
crime_typesMain Fields
id (PK)name, description, icon, color, is_active
offense_typesMain Fields
id (PK)name, crime_type_id, description, is_active
barangays / audit_logsMain Fields
id (PK)barangay name/city/coordinates; audit user/action/old_values/new_values/ip/user_agent

No duplicated type, barangay, user, evidence, or audit information. Easier updates, accurate reports, and better database integrity.
