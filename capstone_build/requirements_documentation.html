Requirements Documentation

Functional Requirements

Common User Requirements

These requirements apply to all authorized system users, including Admin, Police Officer, Investigator, and LGU users.

Login Module

This module allows authorized users to securely access the system using valid credentials.

REQ. CU.1.1 The user shall be able to enter their email address.

REQ. CU.1.2 The user shall be able to enter their password.

REQ. CU.1.3 The system shall validate the user's email and password before granting access to the dashboard.

REQ. CU.1.4 The system shall reject invalid login credentials and display an appropriate error message.

REQ. CU.1.5 The user shall be able to access the forgot password page from the login page.

REQ. CU.1.6 The system shall redirect the user to the dashboard after a successful login.

Forgot Password Module

This module allows users to request password reset assistance when they cannot access their account.

REQ. CU.2.1 The user shall be able to access the forgot password page from the login page.

REQ. CU.2.2 The user shall be able to enter their registered email address.

REQ. CU.2.3 The system shall validate the submitted email address before processing the password reset request.

REQ. CU.2.4 The system shall send password reset instructions or a reset code to the user's registered email address.

REQ. CU.2.5 The user shall be able to proceed to the reset password page after receiving valid reset instructions.

Reset Password Module

This module allows users to create a new password after completing the password reset process.

REQ. CU.3.1 The user shall be able to enter the required reset information.

REQ. CU.3.2 The user shall be able to enter a new password.

REQ. CU.3.3 The user shall be able to confirm the new password.

REQ. CU.3.4 The system shall validate that the new password and confirmation password match.

REQ. CU.3.5 The system shall update the user's password after successful validation.

REQ. CU.3.6 The user shall be able to log in using the new password after the reset is completed.

Dashboard Module

This module provides users with a role-based summary of crime records and system statistics.

REQ. CU.4.1 The user shall be able to access the dashboard after a successful login.

REQ. CU.4.2 The system shall display dashboard information based on the user's role.

REQ. CU.4.3 The system shall prevent the user from viewing dashboard information that is not allowed for their assigned role.

Profile Management Module

This module allows authenticated users to manage their own account settings.

REQ. CU.5.1 The user shall be able to access their profile settings.

REQ. CU.5.2 The user shall be able to update their profile information.

REQ. CU.5.3 The user shall be able to update their password.

REQ. CU.5.4 The system shall validate profile and password changes before saving.

Logout Module

This module allows authenticated users to securely end their session.

REQ. CU.6.1 The user shall be able to log out from the system.

REQ. CU.6.2 The system shall invalidate the user's active session after logout.

REQ. CU.6.3 The system shall prevent logged-out users from accessing authenticated pages without logging in again.

Admin User Requirements

The Admin user has full system access and is responsible for managing records, users, reports, maintenance data, and audit logs.

Admin Dashboard Module

REQ. AU.1.1 The Admin user shall be able to access the dashboard after a successful login.

REQ. AU.1.2 The Admin user shall be able to view total crime incidents, crimes recorded today, crimes recorded this month, and pending crimes.

REQ. AU.1.3 The Admin user shall be able to view crime statistics by crime type.

REQ. AU.1.4 The Admin user shall be able to view hotspot summary information based on barangay crime counts.

REQ. AU.1.5 The Admin user shall be able to view monthly crime trend information.

REQ. AU.1.6 The Admin user shall be able to view crime status breakdown information.

Admin Crime Incident Management Module

REQ. AU.2.1 The Admin user shall be able to view all crime incident records.

REQ. AU.2.2 The Admin user shall be able to create new crime incident records.

REQ. AU.2.3 The Admin user shall be able to enter crime details such as title, crime type, offense type, barangay, date occurred, date reported, and address.

REQ. AU.2.4 The Admin user shall be able to assign a Police Officer as reporter when recording a crime incident.

REQ. AU.2.5 The Admin user shall be able to assign an Investigator to a crime incident.

REQ. AU.2.6 The Admin user shall be able to upload evidence files when creating or updating a crime incident.

REQ. AU.2.7 The Admin user shall be able to search crime incidents by title, case number, offense type, stage of felony, investigation findings, or address.

REQ. AU.2.8 The Admin user shall be able to filter crime incidents by crime type, barangay, status, and date range.

REQ. AU.2.9 The Admin user shall be able to view the full details of a crime incident.

REQ. AU.2.10 The Admin user shall be able to update crime incident information.

REQ. AU.2.11 The Admin user shall be able to archive crime incident records.

Admin Crime Status Workflow Module

REQ. AU.3.1 The Admin user shall be able to update the status of any crime incident.

REQ. AU.3.2 The Admin user shall be required to enter remarks when changing a crime incident status.

REQ. AU.3.3 The Admin user shall be able to record investigation findings.

REQ. AU.3.4 The system shall store the old status, new status, remarks, user, and date of every status change.

REQ. AU.3.5 The Admin user shall be able to view the status history of a crime incident.

Admin Evidence Management Module

REQ. AU.4.1 The Admin user shall be able to upload evidence files for a crime incident.

REQ. AU.4.2 The Admin user shall be able to view uploaded evidence files.

REQ. AU.4.3 The Admin user shall be able to delete uploaded evidence files.

REQ. AU.4.4 The system shall only allow supported evidence file formats such as JPG, JPEG, PNG, PDF, DOC, and DOCX.

REQ. AU.4.5 The system shall limit evidence upload size based on the allowed file size.

Admin Crime Map Module

REQ. AU.5.1 The Admin user shall be able to access the crime map.

REQ. AU.5.2 The Admin user shall be able to view plotted crime incident locations on the map.

REQ. AU.5.3 The Admin user shall be able to view Koronadal City barangay boundaries.

REQ. AU.5.4 The Admin user shall be able to detect the barangay based on selected coordinates.

REQ. AU.5.5 The Admin user shall be able to plot a crime incident from the map.

Admin Hotspot Module

REQ. AU.6.1 The Admin user shall be able to access the hotspot module.

REQ. AU.6.2 The Admin user shall be able to view crime hotspot information.

REQ. AU.6.3 The Admin user shall be able to view crime counts by barangay.

Admin Analytics Module

REQ. AU.7.1 The Admin user shall be able to access the analytics module.

REQ. AU.7.2 The Admin user shall be able to view crime trend data.

REQ. AU.7.3 The Admin user shall be able to view crime distribution by crime type.

REQ. AU.7.4 The Admin user shall be able to view crime distribution by barangay.

REQ. AU.7.5 The Admin user shall be able to view crime status breakdown information.

REQ. AU.7.6 The Admin user shall be able to generate monthly crime report data for a selected year.

Admin Reports Module

REQ. AU.8.1 The Admin user shall be able to access the reports module.

REQ. AU.8.2 The Admin user shall be able to generate report previews.

REQ. AU.8.3 The Admin user shall be able to export reports as PDF files.

Admin User Management Module

REQ. AU.9.1 The Admin user shall be able to view the list of system users.

REQ. AU.9.2 The Admin user shall be able to create new user accounts.

REQ. AU.9.3 The Admin user shall be able to assign user roles such as Admin, Police Officer, Investigator, and LGU.

REQ. AU.9.4 The Admin user shall be able to update user account information.

REQ. AU.9.5 The Admin user shall be able to manage active or inactive user account status when available.

Admin Crime Type Management Module

REQ. AU.10.1 The Admin user shall be able to view crime types.

REQ. AU.10.2 The Admin user shall be able to create new crime types.

REQ. AU.10.3 The Admin user shall be able to update existing crime types.

REQ. AU.10.4 The Admin user shall be able to remove or disable crime types when appropriate.

REQ. AU.10.5 The system shall use active crime types as selectable options when recording crime incidents.

Admin Offense Type Management Module

REQ. AU.11.1 The Admin user shall be able to view offense types.

REQ. AU.11.2 The Admin user shall be able to create new offense types.

REQ. AU.11.3 The Admin user shall be able to update existing offense types.

REQ. AU.11.4 The Admin user shall be able to remove or disable offense types when appropriate.

REQ. AU.11.5 The system shall use active offense types as selectable options when recording crime incidents.

Admin Audit Log Module

REQ. AU.12.1 The Admin user shall be able to access audit logs.

REQ. AU.12.2 The Admin user shall be able to review recorded system activities.

REQ. AU.12.3 The system shall record important actions such as crime creation, crime update, crime archive, status update, and evidence upload.

REQ. AU.12.4 The system shall store audit information for accountability and monitoring.

Police Officer User Requirements

The Police Officer user is responsible for recording crime incidents, viewing related records, using the map, and monitoring hotspots.

Police Officer Dashboard Module

REQ. PO.1.1 The Police Officer user shall be able to access the dashboard after a successful login.

REQ. PO.1.2 The Police Officer user shall be able to view role-based dashboard statistics.

REQ. PO.1.3 The Police Officer user shall be able to view crime type, hotspot, trend, and status summary information available to their role.

Police Officer Crime Incident Management Module

REQ. PO.2.1 The Police Officer user shall be able to view crime incidents they reported or are assigned to.

REQ. PO.2.2 The Police Officer user shall be able to create new crime incident records.

REQ. PO.2.3 The Police Officer user shall be able to enter crime details such as title, crime type, offense type, barangay, date occurred, date reported, and address.

REQ. PO.2.4 The Police Officer user shall be able to enter optional details such as time occurred, time reported, stage of felony, latitude, longitude, and investigation findings.

REQ. PO.2.5 The system shall automatically set the Police Officer user as the reporter of the crime incident.

REQ. PO.2.6 The Police Officer user shall be able to upload evidence files when creating or updating a crime incident.

REQ. PO.2.7 The Police Officer user shall be able to search related crime incidents by title, case number, offense type, stage of felony, investigation findings, or address.

REQ. PO.2.8 The Police Officer user shall be able to filter related crime incidents by crime type, barangay, status, and date range.

REQ. PO.2.9 The Police Officer user shall be able to view the full details of related crime incidents.

REQ. PO.2.10 The Police Officer user shall be able to update crime incidents they are authorized to edit.

REQ. PO.2.11 The Police Officer user shall be able to archive crime incidents they are authorized to edit.

Police Officer Crime Status Workflow Module

REQ. PO.3.1 The Police Officer user shall be able to update the status of authorized crime incidents.

REQ. PO.3.2 The Police Officer user shall be required to enter remarks when changing a crime incident status.

REQ. PO.3.3 The Police Officer user shall be able to view the status history of authorized crime incidents.

Police Officer Evidence Management Module

REQ. PO.4.1 The Police Officer user shall be able to upload evidence files for authorized crime incidents.

Police Officer Crime Map Module

LGU User Requirements

REQ. LU.1.1 The LGU user shall be able to access the dashboard after a successful login.

REQ. LU.1.2 The LGU user shall be able to view role-based dashboard statistics.

LGU Analytics Module

REQ. LU.2.2 The LGU user shall be able to view crime trend data.

REQ. LU.2.3 The LGU user shall be able to view crime distribution by crime type.

REQ. LU.2.4 The LGU user shall be able to view crime distribution by barangay.

REQ. LU.2.5 The LGU user shall be able to view crime status breakdown information.

REQ. LU.2.6 The LGU user shall be able to view monthly crime report data for a selected year.

Non-Functional Requirements

Security Requirements

REQ. NF.1.1 The system shall protect authenticated pages from unauthenticated access.

REQ. NF.1.2 The system shall enforce role-based access control for restricted modules.

REQ. NF.1.3 The system shall store passwords securely using hashing.

REQ. NF.1.4 The system shall validate user input before saving records.

REQ. NF.1.5 The system shall protect file upload functions by limiting file types and file sizes.

Usability Requirements

REQ. NF.2.1 The system shall provide a clear navigation menu based on the user's role.

REQ. NF.2.2 The system shall display success and error messages after important user actions.

REQ. NF.2.3 The system shall allow users to search and filter records to find information efficiently.

REQ. NF.2.4 The system shall present dashboard, analytics, map, and report information in a format that is easy to understand.

Reliability Requirements

REQ. NF.3.1 The system shall maintain stored crime incident records unless they are intentionally archived or removed by an authorized user.

REQ. NF.3.2 The system shall preserve status history for crime incident workflow tracking.

REQ. NF.3.3 The system shall preserve audit logs for accountability.

REQ. NF.3.4 The system shall prevent duplicate case numbers when creating crime incidents.

Performance Requirements

REQ. NF.4.1 The system shall load dashboard statistics, crime lists, maps, analytics, and reports within a reasonable response time.

REQ. NF.4.2 The system shall paginate crime incident lists to support efficient record browsing.

REQ. NF.4.3 The system shall use filters and database queries to retrieve only relevant records when possible.

Data Requirements

REQ. NF.5.1 The system shall store user account information, crime types, offense types, barangays, crime incidents, evidence, status histories, and audit logs.

REQ. NF.5.2 The system shall associate each crime incident with its crime type, offense type, barangay, reporter, assigned officer, evidence files, and status history when available.

REQ. NF.5.3 The system shall store barangay and coordinate information for crime mapping and hotspot identification.

REQ. NF.5.4 The system shall support analytics and reports using stored crime incident data.
